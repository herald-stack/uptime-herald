This is a *structurally separate* build from the desktop `.layout` markup, not a reflow of it. Below the width the fixed 360px sidebar + flexible detail panel needs, the two-pane layout doesn't just get cramped, it stops working outright -- the aggregate stats grid and the check-log's fixed-pixel table columns both need real room. Rather than fight that with an ever-growing pile of overrides, the mobile markup (`.mobile-shell` and everything inside it, in dashboard.html) is its own build with its own JS (dashboard-mobile.js). It borrows the desktop's classes/CSS custom properties for visual identity (`.sidebar-header`, `.sidebar-footer`, `.monitor-list`, `.monitor-row`, `.sidebar-filter`, `.metric-card`, etc. are reused as-is; unscoped class selectors work in any container) rather than sharing DOM structure or click handlers with the desktop path. Breakpoint: 1366px, chosen deliberately (not the classic 768px tablet breakpoint) -- desktop monitors are wider than that, so they get the two-pane `.layout`, and everything else (phones, tablets in either orientation, small laptops) gets `.mobile-shell`. Both `.layout` and `.mobile-shell` are always present in the rendered page; only one is ever visible at a time, chosen purely by this media query — everything is built into the interface and shown/hidden, rather than picking one client-side/server-side at load time. #} .mobile-shell { display: none; } {# .check-log-mobile and .detail-footer-mobile's own "hidden by default" base rules live in _style_common.html, not here — see the comment there for why (kiosk.html renders the same monitor.html fragment as dashboard.html but doesn't include this file at all). #} @media (max-width: 1365px) { .layout { display: none; } .mobile-shell { display: flex; flex: 1; min-width: 0; flex-direction: column; height: 100vh; height: 100dvh; /* see body's rule in _style_common.html for why */ min-height: 0; } /* Header: always visible.
